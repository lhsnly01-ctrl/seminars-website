1. Introduction

Searching for an item in a large collection is one of the most common operations in computing. A hash table solves this problem by computing, from the item's key, the position where its value should be stored, so that lookups, insertions and deletions take constant time on average. Hash tables underlie Python dictionaries and sets, database indexes, caches and symbol tables. In cybersecurity they support fast blocklist checks, file deduplication and log analysis, and they also introduce specific risks, such as algorithmic-complexity denial-of-service attacks.

3. Definition and Key-Value Model

A hash table is a data structure that stores key-value pairs in an array of m slots (called buckets). A hash function h maps each key to an index in the range 0 to m-1. The key identifies the entry (for example an IP address), and the value is the data associated with it (for example a reputation score).

3.1 Basic operations

  • insert(key, value): compute h(key) and store the pair at that index.
  • search(key): compute h(key) and inspect that index.
  • delete(key): locate the entry and remove it.

3.2 Simple illustration

key "alice" --h("alice") = 2--+
key "bob"   --h("bob")   = 5--|--+
                              v  v
index:   0     1     2           3     4     5
       [   ] [   ] [alice:10] [   ] [   ] [bob:7]

4. Hash Functions

A hash function converts a key of arbitrary size into an integer index. A common simple form is the division method: h(k) = k mod m. For strings, the characters are first combined into a number (for example with a polynomial rolling computation) and then reduced modulo m.

4.1 Desirable properties

  • Deterministic: the same key always gives the same index.
  • Uniform distribution: keys spread evenly across buckets to minimise collisions.
  • Fast to compute.
Important distinction: hash functions used in hash tables (such as SipHash) are designed for speed and even distribution. Cryptographic hash functions (such as SHA-256) are additionally designed to be preimage-resistant and collision-resistant. They are not interchangeable: cryptographic hashes are too slow for ordinary table lookups, and table hashes must never be used to protect data.

5. Collisions and Their Handling

Because the set of possible keys is far larger than the number of slots, two different keys will sometimes hash to the same index. This is called a collision. Two standard strategies are used to resolve it.

5.1 Separate chaining

Each bucket holds a collection (typically a linked list) of all entries that hash to it. Colliding keys are simply appended to the same chain.

0: -> [ "bob":7 ] -> [ "eve":3 ]
1: (empty)
2: -> [ "alice":10 ]
3: (empty)

The expected chain length is the load factor α = n / m, where n is the number of stored entries. Keeping α small keeps operations fast.

5.2 Open addressing

All entries are stored directly in the array. When the target slot is occupied, the table probes other slots in a fixed sequence until it finds a free one.

  • Linear probing: try indices i, i+1, i+2, ... (wrapping around). Simple and cache-friendly, but prone to clustering.
  • Quadratic probing: step sizes grow quadratically, reducing primary clustering.
  • Double hashing: the step size comes from a second hash function.

Deletion in open addressing requires a special "deleted" marker so that probe sequences are not broken. The load factor must stay below 1, and performance degrades sharply as it approaches 1.

5.3 Resizing

When the load factor exceeds a threshold, the table allocates a larger array and re-inserts every entry (rehashing). Resizing is expensive but happens rarely, so insertion remains O(1) amortised.

6. Time Complexity

OperationAverage caseWorst case
SearchO(1)O(n)
InsertO(1)O(n)
DeleteO(1)O(n)

The average case assumes simple uniform hashing and a bounded load factor. The worst case occurs when all keys collide into one bucket or one probe sequence, reducing the table to a linear list. This worst case is the basis of the attack described in Section 8.

7. Practical Python Examples

7.1 Built-in dictionary and set

Python's dict and set are hash tables with open addressing.

blocked_ips = {"203.0.113.5", "198.51.100.23"}   # set: hash table of keys only

def is_blocked(ip):
    return ip in blocked_ips        # average O(1)

print(is_blocked("203.0.113.5"))    # True
print(is_blocked("192.0.2.1"))      # False

7.2 Hash table with separate chaining

class ChainedHashTable:
    def __init__(self, size=8):
        self.buckets = [[] for _ in range(size)]
        self.count = 0

    def _index(self, key):
        return hash(key) % len(self.buckets)

    def put(self, key, value):
        bucket = self.buckets[self._index(key)]
        for i, (k, _) in enumerate(bucket):
            if k == key:                    # key exists: update
                bucket[i] = (key, value)
                return
        bucket.append((key, value))
        self.count += 1
        if self.count / len(self.buckets) > 0.75:
            self._resize()

    def get(self, key, default=None):
        for k, v in self.buckets[self._index(key)]:
            if k == key:
                return v
        return default

    def _resize(self):
        old = [pair for bucket in self.buckets for pair in bucket]
        self.buckets = [[] for _ in range(len(self.buckets) * 2)]
        self.count = 0
        for k, v in old:
            self.put(k, v)

t = ChainedHashTable()
t.put("alice", 10)
t.put("bob", 7)
print(t.get("alice"))   # 10

7.3 Linear probing (insertion and lookup)

class ProbingTable:
    def __init__(self, size=8):
        self.keys = [None] * size
        self.values = [None] * size

    def put(self, key, value):
        i = hash(key) % len(self.keys)
        for _ in range(len(self.keys)):
            if self.keys[i] is None or self.keys[i] == key:
                self.keys[i], self.values[i] = key, value
                return
            i = (i + 1) % len(self.keys)   # linear probe
        raise RuntimeError("table is full")

    def get(self, key):
        i = hash(key) % len(self.keys)
        for _ in range(len(self.keys)):
            if self.keys[i] is None:
                return None
            if self.keys[i] == key:
                return self.values[i]
            i = (i + 1) % len(self.keys)
        return None

7.4 Detecting duplicate files by cryptographic hash

import hashlib

def sha256_of(path):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
            h.update(chunk)
    return h.hexdigest()

seen = {}                       # hash table: digest -> first path
def check(path):
    digest = sha256_of(path)
    if digest in seen:
        print(path, "duplicates", seen[digest])
    else:
        seen[digest] = path

Note: the probing example omits deletion and resizing for brevity.

8. Applications in Cybersecurity

  • Blocklists and allowlists: firewalls, intrusion detection systems and mail filters check IP addresses, domains or file hashes against large sets in constant average time.
  • Malware signature lookup: antivirus tools store known-malicious file digests (for example SHA-256) in hash-based structures for fast matching.
  • Log and event analysis: counting events per source IP or username with a dictionary helps detect brute-force attempts or scanning.
  • Deduplication and integrity checking: file digests identify identical or modified files.
  • Password storage: systems should store salted, deliberately slow password hashes (such as bcrypt, scrypt or Argon2), not plain hashes and not hash-table indices.
  • Bloom filters: a space-efficient probabilistic structure built from several hash functions, used for membership tests such as malicious URL filtering. It can give false positives but never false negatives.
  • Hash-flooding denial of service: Crosby and Wallach (2003) showed that an attacker who can predict a table's hash function can craft many colliding keys, pushing operations toward O(n) and exhausting CPU. Mitigations include keyed, randomised hash functions such as SipHash, which modern language runtimes (including Python) use for string keys.

10. Conclusion

Hash tables provide average constant-time access by mapping keys to array positions through a hash function. Their performance depends on a good hash function, an appropriate collision strategy and a controlled load factor. For cybersecurity students, they are both a practical tool for building fast detection and analysis programs and a case study in how an assumption about average behaviour can be exploited by an attacker. Understanding the difference between table hashing and cryptographic hashing is essential for using each correctly.
